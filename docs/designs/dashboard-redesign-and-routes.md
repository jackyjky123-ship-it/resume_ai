## 1. Problem Statement

Students and entry-level job seekers frequently suffer from **blank-page paralysis** when creating their first CV or modernizing an outdated resume (e.g. someone applying to be a barista, retail associate, or junior engineer who doesn't know how to articulate responsibilities or highlight transferable skills).

Commercial resume builders (Zety, Novoresume, Resume.io) bait users with "free" editing and hold the PDF download hostage behind \$20–\$30/month recurring subscriptions. Meanwhile, open-source or free alternatives lack guided AI assistance, look dated, and don't provide clean, ATS-compliant multi-page typography.

**Resume AI solves this by being 100% free and open source**, powered by a **Bring-Your-Own-Key (BYOK)** Google Gemini architecture. Users plug in a free Google AI Studio key and get instantaneous, professional CV generation without paywalls.

To deliver this value without cognitive overload, the existing single-page card grid dashboard must evolve into a structured SaaS platform with a persistent sidebar, dedicated template gallery, interactive API setup guide, and usage analytics.

## 4. Architectural Requirements & Constraints

1. **Next.js 16 App Router Compliance (`cacheComponents: true`)**:
   - Layout must stream data properly. All session checks (`requireUser()`) occur in RSC boundaries wrapped in `<Suspense>`.
   - Nested layout `src/app/dashboard/layout.tsx` will house the persistent sidebar so navigating between `/dashboard`, `/dashboard/templates`, and `/dashboard/api` does not reload the navigation shell.
2. **Database & Schema Invariance**:
   - The database stores `templateId` as `classic`, `modern`, `compact`, `professional`, `editorial`, `designer`.
   - To fulfill the user's requirement ("change template name instead compact designer to Template 01, Template 02"), we keep the internal IDs unchanged in Prisma and map user-facing labels to:
     - `classic` → **Template 01**
     - `modern` → **Template 02**
     - `compact` → **Template 03**
     - `professional` → **Template 04**
     - `editorial` → **Template 05** (Recommended)
     - `designer` → **Template 06** (Recommended)
3. **Bring Your Own Key (BYOK) Security**:
   - API keys are stored in `localStorage` or encrypted session cookies on the client side; never logged to server consoles or stored in public tables.
   - The API route provides an in-app tester that runs a lightweight ping (`gemini-1.5-flash` or `gemini-2.0-flash`) to confirm validity immediately.

## 6. Route-by-Route Detailed Specifications

### Route 1: Overview Dashboard (`/dashboard`)
- **Top Bar / Hero:**
  - Personalized greeting ("Welcome back, {User}") with subtitle for students ("Ready to craft your next opportunity?").
  - Primary Action Button: `+ Create CV` which opens the creation dialog (Title input + Template picker default to Template 01).
- **"Static Use" Usage Analytics:**
  - 4 quick metric tiles:
    1. **Total CVs Created:** Count of resumes in user's account.
    2. **Primary Template:** Most-used template by the user (e.g. "Template 05").
    3. **Content Readiness:** Average section completion percentage across resumes.
    4. **AI Generation Status:** Indicates if Gemini API Key is configured and ready.
- **"See All Data" Resume Workspace:**
  - Search input, template filter dropdown, and sort options (Last edited, Alphabetical, Date created).
  - Responsive grid of resume cards with live mini-previews, filled-section indicator dots, last edited timestamp, and quick-action menu (Edit, Duplicate, Rename, Export PDF, Delete).
  - Empty state with guidance for first-time students on how to start their first CV.

### Route 2: Templates Showcase (`/dashboard/templates`)
- **Display Name Mapping:**
  - Clean numbers: **Template 01** through **Template 06**.
  - Internal names remain subtitles for clarity (e.g., `Template 01 (Classic)`, `Template 05 (Editorial - Recommended)`).
- **Recommendation Badges:**
  - `Template 05` and `Template 06` get a highlighted "Recommended / Most Popular" badge (especially popular for students showcasing projects and modern layouts).
- **Interactive Action:**
  - Each template card features a high-fidelity visual preview, bulleted list of best-fit roles (e.g., "Best for Barista, Customer Service, Tech"), and a direct `"Use Template"` button that initializes a new resume pre-set to that template.

### Route 3: API Setup & Connection Guide (`/dashboard/api`)
- **Visual Student-Friendly Guide:**
  1. **Step 1:** Open [Google AI Studio](https://aistudio.google.com/app/apikey) in a new tab.
  2. **Step 2:** Click **"Create API Key"** (free tier includes 15 RPM, no billing or credit card required).
  3. **Step 3:** Paste the key into the input field below.
- **Key Validation & Local Persistence:**
  - Interactive test button: sends a minimal prompt ping to test key validity.
  - Visual status pill: `Active & Connected` (Green) or `Not Connected` (Amber).
  - Security reassurance: Clear notice that the key is stored locally in the browser and never transmitted to our database.

### Bottom Sidebar: Settings Slide-over / Modal
- Accessible via the gear icon `Settings` anchored at the bottom of the sidebar.
- **Tabs / Sections:**
  1. **Account Profile:** Display user's name, email, and joined date.
  2. **AI Provider:** Quick toggle to view or update the Gemini API key.
  3. **Preferences:** Template defaults and interface settings.
  4. **Session:** Direct Sign Out button.

## 7. Implementation Plan

1. **Step 1: Update Metadata (`src/lib/resume-meta.ts`)**
   - Add `displayLabel: "Template 01"`, `"Template 02"`, etc., and `isRecommended: boolean` flags.
2. **Step 2: Create Persistent Dashboard Layout (`src/app/dashboard/layout.tsx` & `src/components/dashboard/dashboard-sidebar.tsx`)**
   - Build a responsive sidebar with navigation links (`/dashboard`, `/dashboard/templates`, `/dashboard/api`), logo, and bottom Settings trigger.
3. **Step 3: Refactor Main Dashboard Overview (`src/app/dashboard/page.tsx` & workspace components)**
   - Add the "Static Use" analytics cards.
   - Refactor "See all Data" resume management table/grid with creation trigger.
4. **Step 4: Build Templates Route (`src/app/dashboard/templates/page.tsx`)**
   - Create gallery showcase for Template 01 to 06 with recommended badges and "Use this Template" flow.
5. **Step 5: Build API Guide Route (`src/app/dashboard/api/page.tsx`)**
   - Implement the student-focused Gemini connection guide and live key tester.
6. **Step 6: Build Settings Modal (`src/components/dashboard/settings-dialog.tsx`)**
   - Wire the bottom settings trigger to manage profile, API key, and account actions.
7. **Step 7: Verification & Testing**
   - Verify all routes with `npx tsc --noEmit`, `npm run lint`, and browser automated checks.
